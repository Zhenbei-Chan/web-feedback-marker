# 技术计划：AI 页面检查

## 目标

在不破坏本地优先和低权限原则的前提下，增加用户主动触发的 AI 页面检查能力。AI 结果先作为“待确认”结果出现；用户确认后转为正式人工反馈，剩余待确认结果在 PDF 最后展示。

## 按钮命名

使用：`AI 检查页面`。

不使用：`扫描低错`。原因是“低错”偏内部术语，对普通用户不够清晰。

## 数据模型

AI 结果保存到：

```json
{
  "webFeedbackAssistant.aiFindings": []
}
```

单条 AI 结果结构：

```json
{
  "id": "ai_...",
  "source": "ai",
  "pageUrl": "https://example.com",
  "pageTitle": "页面标题",
  "createdAt": "2026-06-27T00:00:00.000Z",
  "status": "pending",
  "category": "内容错误",
  "errorType": "错别字",
  "issue": "这里可能存在错别字。",
  "originalText": "原文片段",
  "suggestedText": "建议文本",
  "reason": "判断原因",
  "confidence": 0.82,
  "severity": "medium",
  "context": "用于定位的上下文",
  "locationStatus": "exact | unmapped",
  "renderMode": "marker | listOnly",
  "shape": null
}
```

状态规则：

- `pending`：待确认，默认状态。
- `dismissed`：内部保留语义，目前用户点击“非问题”时直接删除，不保留在列表。
- 用户点击 `加入反馈/确认问题` 时，AI 结果转为正式人工反馈，并从 AI 待确认列表移除。
- 已转为人工反馈的 AI 结果不再作为 AI 结果导出。

## Provider 方案

采用 BYOK 模式，用户自己配置 API Key。开源仓库不包含任何 Key。

第一版支持：

- 智谱 AI 预设。
- DeepSeek 预设。
- OpenAI-compatible 自定义服务。
- Mock 测试模式。

百度千帆暂不作为第一版内置预设，避免引入更复杂的鉴权流程。

## 权限策略

1. `manifest.json` 保持基础权限：`activeTab`、`scripting`、`storage`、`notifications`。
2. AI 服务域名使用 `optional_host_permissions`。
3. 用户保存 AI 设置时，根据 Base URL 请求对应域名权限。
4. 用户拒绝权限时，AI 检查不可用，但人工批注、HTML/PDF 导出不受影响。

## 文本抽取

- 只抽取可见正文文本。
- 跳过 `script`、`style`、`svg`、插件自身 UI、隐藏元素和表单输入内容。
- 优先正文区域，尽量跳过导航、目录、页脚、推荐列表等公共区域。
- 默认最多选取 12 个正文文本块，避免长页面请求过慢。
- 每块携带 block id 和文本，用于 AI 返回结果定位。

## AI 输出协议

要求模型只返回 JSON 数组：

```json
[
  {
    "block_id": "block_1",
    "error_type": "错别字",
    "original_text": "确诊按钮",
    "suggested_text": "确认按钮",
    "reason": "此处语境是操作确认。",
    "severity": "medium",
    "confidence": 0.82,
    "context": "请点击下方的确诊按钮提交表单"
  }
]
```

插件侧容错：

- JSON 解析失败时显示中文错误。
- 缺少原文、建议或原因时丢弃。
- 原文与建议相同或仅空格/大小写差异时丢弃。
- 错别字建议必须保留原文语义、词性和语气；疑似近义词替换、语义改写时丢弃。
- 常见确定性错词可走本地规则修正，例如 `属是` 在表示确实、的确的语境中修正为 `属实`，避免模型误改成 `似乎`。
- 主观风格建议、标题吸引力建议、普通改写建议默认过滤。
- 同一文本位置重复结果合并。
- 无法定位到页面时，进入清单但不绘制页面坐标标记。

## 页面交互

- AI 待确认使用琥珀色手绘下划线和编号。
- 能定位原文时显示页面标记。
- 不能定位原文时只保留在反馈清单。
- 点击 `加入反馈`：转为正式人工反馈。
- 点击 `非问题`：删除该 AI 结果。

## 导出规则

PDF 顺序：

1. 报告标题和页面信息。
2. 人工反馈列表。
3. 剩余 AI 待确认结果。

导出规则：

- 人工反馈优先。
- 已加入反馈的 AI 结果按人工反馈展示。
- 非问题已删除，不导出。
- AI 待确认结果显示状态、分类、原文、建议和原因。
- 日期默认不展示具体时分秒。

## 非目标

- 不自动修改网页。
- 不上传截图。
- 不做 OCR。
- 不做云同步。
- 不做多人协作。
- 不承诺第三方模型免费或稳定。

## 主要风险

- AI 误报不可避免，所以必须保留待确认流程。
- 复杂网页 DOM 文本定位可能失败，需要 list-only 结果承接。
- API Key 保存在 `chrome.storage.local`，不是加密保险箱。
- 系统通知受 Chrome 和操作系统设置影响，需要失败原因日志。\n- 长页面或服务繁忙时可能触发超时；插件会拆小文本块并自动重试，但仍需保留人工重试入口。
